API는 이미 매일 쓰고 있었습니다

새로운 기술을 배우는 게 아닙니다. 앱에서 버튼을 누를 때마다 일어나던 일에 이름을 붙이는 시간입니다. 식당에서 주문하는 것과 똑같은 구조라는 걸 먼저 확인해 봅시다.

오늘 새로 배울 말은 넷뿐

  • 요청 — 무언가 해달라고 보내는 것
  • 응답 — 그에 대한 답
  • JSON — 답을 적어 보내는 형식
  • 상태 코드 — 잘 됐는지 알려주는 숫자
이 시간이 끝나면웹사이트 뒤에서 무슨 일이 오가는지 눈으로 볼 수 있게 됩니다. 코드는 한 줄도 쓰지 않습니다.

왜 새로고침을 해야 최신이 보일까

4교시

AI는 왜 내 폴더를 못 볼까

AI에게 파이썬 문법을 물으면 잘 답합니다. 그런데 "내 폴더에 뭐 있어?"라고 물으면 못 합니다. 아는 것과 볼 수 있는 것은 다르기 때문입니다. MCP는 이 틈을 메우는 약속입니다.

이번 시간 새 낱말

  • 도구 — AI가 부를 수 있는 기능
  • MCP — 도구를 붙이는 공통 약속
  • MCP 서버 — 도구를 제공하는 프로그램
  • 설정 파일 — 무엇을 붙일지 적어두는 곳
이 시간이 끝나면남이 만든 MCP 서버를 붙여서 AI가 내 폴더를 읽게 만들 수 있습니다.

5교시

2교시에 만든 API를 AI에게 열어주기

새로 배울 게 많지 않습니다. 이미 만든 함수 위에 한 줄만 붙이면 AI가 부를 수 있는 도구가 됩니다. 다만 AI는 코드를 읽지 않고 설명을 읽는다는 점이 중요합니다.

이번 시간 새 낱말

  • @mcp.tool() — 이 함수를 도구로
  • 설명문 — AI가 읽는 사용 안내
  • Inspector — 도구를 확인하는 화면
  • 권한 — AI에게 무엇까지 허락할지
이 시간이 끝나면내 주문 API를 AI가 부를 수 있게 만들고, 설명문이 왜 중요한지 알게 됩니다.

할 수는 있는데 잘 못할 때

도구를 아무리 붙여도 "우리 회사 양식대로"는 해결되지 않습니다. 능력이 없는 게 아니라 방법을 모르는 것이기 때문입니다. 마지막으로 오늘 배운 넷을 언제 쓰는지 정리합니다.

이번 시간 새 낱말

  • Skill — 잘하는 방법을 적어둔 안내서
  • SKILL.md — 그 안내서 파일
  • 설명(description) — 언제 쓸지 알려주는 줄
  • 도구와 방법 — 둘은 다른 문제
이 시간이 끝나면SKILL.md를 한 장 쓸 수 있고, 넷 중 무엇을 쓸지 고를 수 있습니다.
